# Patrones de .gitignore para Next.js + Prisma

## Archivos que NUNCA deben subirse (git add . agregará automáticamente, pero hay que verificar)

### Obligatorios (siempre en .gitignore):

```
/node_modules
/.next/
.env
.env*.local
prisma/dev.db
prisma/dev.db-journal
```

### Explicación:

- **`/node_modules`**: Dependencias npm. Se instalan con `npm install` en cada entorno.
- **`/.next/`**: Build output de Next.js. Se regenera con `npm run build`.
- **`.env`**: Variables de entorno sensibles. NUNCA commitear credenciales.
- **`.env*.local`**: Variantes locales de env (development, testing, etc.).
- **`prisma/dev.db`**: Base de datos SQLite local de desarrollo.
- **`prisma/dev.db-journal`**: WAL journal de SQLite (puede contener datos parciales).

### ✅ Archivos SÍ commiteables:

- `prisma/schema.prisma` - Definición del modelo de datos
- `prisma/seed.mjs` - Datos de prueba/seed
- `prisma/migrations/` - Histórico de migraciones (SQL files)
- `next.config.js` - Configuración de Next.js
- `tailwind.config.js` - Configuración de Tailwind (si se usa)
- `tsconfig.json` - Configuración TypeScript
- `package.json` - Dependencias y scripts

### .gitignore Completo Ejemplo:

```gitignore
# Dependencias
/node_modules
/.next/

# Entorno
.env
.env*.local

# Base de datos local
prisma/dev.db
prisma/dev.db-journal

# TypeScript
*.tsbuildinfo
next-env.d.ts

# Sistemas operativos
.DS_Store
```

### Advertencias Importantes

1. **Nunca commitear `.env`**: Contiene credenciales (DB passwords, API keys, secrets).
2. **Usar `cross-env` en scripts**: Para variables de entorno en scripts npm.
   ```json
   "scripts": {
     "build": "cross-env NODE_ENV=production next build"
   }
   ```
3. **En equipos**: Compartir `.env.example` (sin valores sensibles), no `.env` real.
4. **En Vercel**: Configurar variables en el panel, no en el archivo `.env`.

### Herramientas de Validación

- `npx gitignore` - Generar .gitignore para tu stack tecnológico
- `husky` + `lint-staged` - Validar antes de commit
- `vercel/build-command` - Verificar configuración antes de deploy
